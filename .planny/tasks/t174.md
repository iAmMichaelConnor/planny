Operator question 2026-09-01: can hand-adding files to .planny/ be prevented? No excusable mechanism exists — permissions tricks break the CLI itself and watchers are racy daemons — so the design is convention (the skill's adding-is-a-mutation law, t161), visibility (store-stamped confirmations, t162) and detection. The detection layer has a gap: doctor never looks for files in .planny/tasks/ that the CLI did not write. Done looks like: doctor reports a finding for any file in tasks/ whose name is not tNN.md, and for any tNN.md missing the frontmatter the CLI always writes (id, name, status, type, kind, priority, created); a hand-dropped id above the allocator's next id gets its own finding, because it causes a future collision. Detection only — repairs stay manual, because the one right answer does not exist. Red first in test/doctor.test.ts.
