Add a "definition of done" to the skill's task-authoring guidance. The skill (skills/planny/SKILL.md, "Creating tasks and plans") already asks the description to say "what done looks like". Make that a named part of every task with examples, so an owner closes a task on evidence and not on feeling. Examples: "all tests green on the branch, rebased on the tip", "merged onto the feature branch and the gate green", "review returned with no blocking finding", "the operator answered".

Add the pattern for work that has two owners, which is the common case when an agent builds and an orchestrator lands. The orchestrator opens two tasks: a parent whose definition of done is "merged" (owned by the orchestrator, closed on the merge with the merge commit appended) and a child whose definition of done is "all green" (owned by the agent, closed when the branch is rebased and every gate passes, with the hand-off in the body). The agent never closes the parent; the orchestrator never closes the child. The board then shows "green, waiting to land" as an open parent over a done child instead of hiding it inside one task with two meanings of done.

The operator's words (2026-09-02): "what tasks are missing when they're opened is a 'definition of done', and we could include examples like you've discussed, like all green, or merged. And an orchestrator could create two tasks: a parent and a child: the parent having a defn of done of 'merged' and the child having the defn of done of 'all green'."
