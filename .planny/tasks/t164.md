Verified 2026-09-01: planny add from a nested subdir walks up and writes to the root store (good — store.ts discovery). But planny init, run in a subdir of a project that already has a .planny store, silently creates a second nested store. Every command run in that subtree then targets the nested store, so the plan silently splits — the exact hazard t161 and t162 describe, but caused by init rather than cwd confusion. Done looks like: init walks up first; when an ancestor .planny exists it refuses, names the existing store root, and asks for an explicit flag (for example --nested) to create one anyway. Red first: a cli.test.ts case where init inside a store's subdir exits 1 and creates nothing, then a case where the flag creates the nested store. Pointers: src/store.ts (discovery walk), src/cli.ts (init command), test/cli.test.ts (init describe).
