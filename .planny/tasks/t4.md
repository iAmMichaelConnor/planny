Publish planny to npm through the GitHub Actions workflow, so the
token never touches any development machine. Every step happens in your
browser. Total time: about five minutes.
 
**Step 1 — create an npm token (~2 min)**

1. Sign in at https://www.npmjs.com.
2. Click your avatar (top right) → **Access Tokens**.
3. Click **Generate New Token** → **Granular Access Token**.
4. Fill in:
   - Token name: `planny-publish`
   - Expiration: 30 days (short on purpose — Step 5 deletes it anyway)
   - Packages and scopes → Permissions: **Read and write**
   - Select packages: choose **All packages**. (A brand-new package name
     cannot be selected before it exists; the short expiry bounds the risk.)
5. Click **Generate token** and copy the long string. It is shown once —
   keep the tab open until Step 2 is done.

**Step 2 — give the token to GitHub as a secret (~1 min)**

1. Open https://github.com/iAmMichaelConnor/planny/settings/secrets/actions
   (that is: the repo → Settings → Secrets and variables → Actions).
2. Click **New repository secret**.
3. Name: `NPM_TOKEN` — exactly that, capitals and underscore.
4. Secret: paste the token. Click **Add secret**.

GitHub encrypts it. Nobody can read it back — not this machine, not its
admin, not even you.

**Step 3 — run the publish workflow (~1 min)**

1. Open https://github.com/iAmMichaelConnor/planny/actions.
2. Click **Publish to npm** in the workflow list on the left.
3. Click the **Run workflow** dropdown (right side), keep branch `main`,
   press the green **Run workflow** button.
4. Wait a couple of minutes. A green tick = published.

**Step 4 — verify**

From any terminal on any machine:

    npm install -g planny
    planny --help

And https://www.npmjs.com/package/planny now exists.

**Step 5 — throw the token away (recommended, any time after Step 4)**

1. On npmjs.com, open the package → **Settings** → **Trusted Publisher**:
   select GitHub Actions, repository `iAmMichaelConnor/planny`,
   workflow `publish.yml`. Save.
2. Delete the `NPM_TOKEN` secret on GitHub (same page as Step 2) and
   revoke the token on npmjs.com (Access Tokens page).

Publishing keeps working via OIDC with no stored credential anywhere.

**If the workflow fails**: click the red run and read which step broke.
The common first-run failure is a token without write permission for new
packages — regenerate the token with Read-and-write on All packages.
