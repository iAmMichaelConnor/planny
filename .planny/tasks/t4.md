Publish planny to npm through the GitHub Actions workflow. Two runs
have failed so far; the setup is now correct and the remaining blocker
looks transient. Current state, 2026-08-31 evening:

**Already done — do not redo:**

- The `NPM_TOKEN` repository secret is set and works. The first run
  failed with a 403 because the npm account requires 2FA for publishes
  and the first token lacked the bypass setting; the regenerated token
  fixed that. (If a token must ever be made again: on the granular
  access token form, tick "Bypass two-factor authentication" — it is
  off by default, and CI cannot answer an interactive 2FA prompt.)
- The workflow itself is correct. Tests, build, and the provenance
  signature all pass on every run.

**The remaining blocker — a 409 from the registry:**

The second run failed at the final upload with
`409 Conflict - Failed to save packument`. The registry record at
https://registry.npmjs.org/planny shows why the name is not fresh:
this same account published `planny@0.0.1` on 2025-05-25 and
unpublished it on 2025-10-09. Republishing onto an unpublished
(tombstoned) name is the classic trigger for this 409, and it is
usually transient.

**Next steps:**

1. Wait 10–15 minutes, then re-run the workflow: repo → Actions →
   **Publish to npm** → **Run workflow** on `main`. A green tick =
   published.
2. If the 409 repeats, retry once or twice more with an hour between
   attempts.
3. If it still fails after that, the tombstone needs npm's help:
   contact npm support (https://www.npmjs.com/support) referencing the
   unpublished `planny@0.0.1`, or decide on a different package name
   (that would be a new decision task — the README, skill, and docs
   all say `planny`).

**After the first green run:**

1. Verify from any machine: `npm install -g planny && planny --help`,
   and https://www.npmjs.com/package/planny exists.
2. On npmjs.com, open the package → **Settings** → **Trusted
   Publisher**: select GitHub Actions, repository
   `iAmMichaelConnor/planny`, workflow `publish.yml`. Save.
3. Delete the `NPM_TOKEN` secret on GitHub (repo → Settings → Secrets
   and variables → Actions) and revoke the token on npmjs.com (Access
   Tokens page). Publishing then works via OIDC with no stored
   credential anywhere.
