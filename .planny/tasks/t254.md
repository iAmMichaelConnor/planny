Why: the board has no URLs. Every view lives at `/`, so an operator cannot
bookmark the decisions tab, cannot reopen the task they were reading after a
restart, and cannot paste a teammate a link to one task. Today the only way
to send someone to a task is to tell them the id and let them type it into
the search box.

Done looks like: the address bar tracks the view and the open task, as
`/?view=decisions` and `/?view=board&task=t42`. Opening such a link selects
the tab and opens the drawer on that task. Changing tabs or opening a task
rewrites the address without adding a history entry; the browser's back
button returns to the previous task or tab. An unknown id in the link raises
the same warning the search box gives and opens the default view.

Files: web/app.js (a small router beside the existing tab and drawer state),
test/ui.test.ts.


Built, 2026-09-02. The address bar now carries the view and the open task:
/?view=board, /?view=decisions, /?view=board&task=t42. Opening such a link
selects the tab and opens the drawer on that task. An unknown id raises the
same warning the search box gives and leaves the drawer shut.

The design in one sentence: the state is the source of truth and the address
follows it. syncUrl runs after every render and after every drawer render,
and writes only when the address would actually change — so a background
refresh, a live event or a poll adds nothing, while a real move pushes one
entry and the back button works. A popstate applies the address back to the
state, and the sync that follows finds nothing left to write, so no flag is
needed to stop the two from fighting.

One correction to the plan above, which contradicted itself: it asked for
"no history entry" and a working back button at the same time. Back needs
entries. A real move — a new tab, a different task, closing the drawer —
pushes one; nothing else does.

Files: web/app.js. Tests: test/ui.test.ts (6). One harness change: each test
boot now resets the address, because the app writes to it and a leftover one
would steer the next test.
