## What

The README presents `planny serve` and `planny url` (the quick-start block and the commands table) with no lifecycle note. An agent that starts the server through its harness's background-task feature loses it when the harness reaps session-scoped tasks — Claude Code stops background commands at session end, /clear, and context compaction. An operator's own terminal has no such problem. On 2026-09-01 this killed a served board twice in one overnight session; the detached form below survived the session's end.

## Done looks like

A one- or two-sentence note beside the serve documentation (the commands table row and/or the server docs page), saying: from inside an agent session, start the server detached — `setsid nohup planny serve --port <port> >/tmp/planny-serve-<port>.log 2>&1 &` — because agent harnesses tie background tool tasks to the session and reap them; from a normal terminal, plain `planny serve` is fine. Keep it with the serve command; do not add a new section.

## Pointers

README.md — the quick-start block that shows `planny serve` and the commands table row for `serve [--port]`. The skill-side counterpart of this change is its own task; the two should agree on wording.
