Why: dragging a card from one column to another is the gesture people expect
from a kanban board, and the board now supports dragging within a column
(t248). Today a drop on another column is refused, because it would be two
acts at once — a move and a status change — and the status buttons already do
the second one.

Done looks like: a card dropped in another column changes status to that
column's status, and lands at the priority position where it was dropped. The
two changes reach the store as they do now: the status route, then the bump.
A drop on the Cancelled column is refused, because cancelling asks about
replacements and that belongs in the drawer. A drop on Parked asks for the
wake note, the same prompt the park button raises.

Open point, worth settling before building: what the operator has to confirm.
Today every priority move and every status change raises a confirm dialog, so
one drag would raise two. Decision t258 asks whether those dialogs stay; build
this after that answer, or the gesture ships twice as slow as it should feel.


Built, 2026-09-02, after the operator answered t258 with the undo.

One gesture, two meanings. A card dropped inside its own column takes a new
priority, as before. A card dropped on another column takes that column's
status, and the place it landed in when that column is ranked. Both halves go
through the same routes the buttons use, so every rule holds: the dependency
clamp on the move and its warning when it bites, the wake note on a park.

The rules the drop follows:
- Dropped on Parked, it asks for the wake note first. Cancel calls off the
  whole drop, note and move together.
- Dropped on Done, only the status changes: a finished task holds no rank, so
  there is no position to name.
- Dropped on a column with no card to sit against — an empty In progress, or
  the space below the last card — only the status changes and the rank stays
  where it was. There is no honest position to invent.
- Dropped on Cancelled, nothing happens and no line is drawn. Cancelling
  rewires the tasks that waited on the cancelled one onto its replacements,
  and that question belongs in the drawer where it can be answered.
- Dropped inside Done, nothing happens: that column holds no order.

Beyond the task as written: a finished card is draggable again, so a task
marked done by mistake can be pulled back into a working column. Only a
cancelled card cannot be picked up.

One undo takes back both halves. It restores the status first, so the task is
ranked again before its old position is asked for, and it skips the position
entirely for a task that had none — a card dragged out of Done — because bump
refuses a target of 0. act() now takes a list of requests and a list of
inverses, which is the whole change needed to make one gesture with two
changes undo as one.
