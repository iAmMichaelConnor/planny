## What

The skill's "Serve the board at session start" bullet says: "start `planny serve` as a background process and tell the operator the URL." In Claude Code, a background tool command belongs to the session. The harness stops it when the session ends, when the operator runs /clear, and when the context window compacts. A long or overnight session compacts, so the board dies mid-session, and the agent may not notice. A resumed session does not restore background commands either (Claude Code sessions docs; anthropics/claude-code issue #25188 tracks this). Every Claude Code user of this skill will hit it; it is not one machine's misconfiguration. Other harnesses have their own lifecycles, but session-scoped background tasks are a common shape.

## Evidence

On 2026-09-01 at about 00:46, an overnight Claude Code session served a board with the harness background-task feature. The harness stopped it twice ("Background command ... was stopped"), each restart killed within a minute. The detached form survived that session's end and a later /clear, and was still serving twelve hours on:

    setsid nohup planny serve --port 5892 >/tmp/planny-serve-5892.log 2>&1 &

`setsid` gives the server its own process session, so the harness's cleanup does not reach it; the redirect plus `nohup` keeps it alive and logging with no terminal.

## Done looks like

The serve bullet in skills/planny/SKILL.md describes both ways and steers the agent to the one that survives:

1. Detached — the default for an agent session. In a normal foreground shell call: `setsid nohup planny serve --port <port> >/tmp/planny-serve-<port>.log 2>&1 &`, then confirm with `planny url`. The server outlives the agent session, so the operator's board stays up.
2. A harness background task — acceptable only when the board matters just for the current sitting; the harness kills it at session end, /clear, or compaction.

Keep the existing order (check `planny url` first) and the ssh -L forward note. Note that macOS ships no `setsid` binary, so the bullet should say what to do there (plain `nohup ... &` from the agent, or the operator's own terminal) unless `planny serve --detach` ships first — see the related decision task — in which case the recipe becomes that single command and this bullet cites it instead.
