Why: an operator who leaves the board and comes back cannot see what the
agents did while they were away. Tasks appear, statuses move and priorities
shift with no mark on them. The CLI already answers this question for agents
with `planny catchup`, which keeps a cursor per consumer and reports every
task changed since that consumer last asked. The board has nothing.

Done looks like: the board remembers, per browser, when this operator last
looked at it. Anything created or changed after that moment carries a mark —
a dot on the card and a line in the drawer saying what changed and when. A
header control clears the mark ("mark all as seen") and says how many tasks
carry it. The mark survives a reload and a live refresh; opening a task
clears its own mark.

Notes: the store keeps `updated` on every task and a typed `history` of every
status change, priority move, re-parent, dependency edit and rename, so the
board needs no new server state — read the browser's last-looked stamp from
localStorage and compare. Do not use a planny catchup cursor for this: those
belong to agents, and one browser reading them would eat another consumer's
delta.

Related: t251 filters by dates, which answers a different question — "show me
a window" rather than "show me what is new to me".


Built, 2026-09-02. The board remembers, per browser, the moment the reader
last marked the plan as seen. Anything the store touched after that moment
carries a dot — on the card and on the tree row — and the header says "N new
since you last looked" beside a "mark all seen" button.

Details worth knowing:
- A first visit marks nothing. Everything would be new, which says nothing;
  it starts the clock instead, so the next visit means something.
- Opening a task clears its own mark. The browser stores the `updated` stamp
  the task carried when it was read, not just its id, so the same task turns
  new again the next time the store touches it.
- "Mark all seen" moves the moment on and empties the per-task record, which
  is dead weight once the moment passes.
- Both marks live in localStorage, so two people watching one board keep
  their own reading, and nothing is written to the store.

As the task said: no catchup cursor was used. Those belong to agents, and a
browser reading one would eat another consumer's delta.
