The detach suite (test/detach.test.ts) launches real detached servers, and each child writes its log to the real OS temp dir via detachLogPath (src/server.ts:137). Every test run leaves files behind. Evidence on the dev machine, 2026-09-01: /tmp holds about 40 planny-serve-<random port>.log husks of 70 bytes each ('error: port N is in use by something else') from the foreign-port test, and planny-serve-0.log grows on every run because a --port 0 request names the log by the requested port, not the bound one. Fix: run the CLI under a per-suite TMPDIR pointing at the suite's mkdtemp dir — node's os.tmpdir() honors TMPDIR on POSIX, and detachServer's child inherits the environment — or delete the log files in afterEach beside the pid reaping (test/detach.test.ts:54). Done looks like: a full npm test leaves no new planny-serve-*.log in the real temp dir; verify by listing the glob before and after a run. Related design decision: t216.

Built: test/detach.test.ts cli() now runs the CLI with TMPDIR pointed at the per-test dir, so the detached server's log lands there and dies with the dir; a test asserts the printed log path is inside it.
