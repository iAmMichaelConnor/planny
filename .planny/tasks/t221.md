## Background

The detached server's log lives at `<tmpdir>/planny-serve-<port>.log`
— keyed by requested port only, one shared flat namespace for the
whole machine (detachLogPath, src/server.ts). Nothing in the path says
which project a log belongs to. Consequences: two projects that both
use the default port 5891 write to the same file over time; a `--port
0` launch always writes to the catch-all `planny-serve-0.log`; on a
shared Linux machine another user's file at the same name makes detach
fail with a permission error; and `serve --clean-logs` (built
2026-09-01) can only sweep by name pattern, so it deletes other
projects' logs too. The operator asked whether the paths are sensibly
siloed by project, said deleting another project's logs is unwanted,
and suggested a "global" clean could stay available.

## Why this comes to you (the operator)

This moves a file you look at for post-mortems, and it reshapes the
`--clean-logs` command you specified earlier today.

## Proposal

Move the log into the store: `.planny/serve.log`.

One server per store is already the model (`serve.json` lives there),
so one log per store beside it makes the silo exact by construction.
The repo's existing `*.log` gitignore rule (and the `serve.json`/`lock`
precedent) covers it. `--clean-logs` then acts on the current project
only — it deletes this store's `serve.log` when the server is dead and
the file is older than `--older-than` days — plus, for one release, the
legacy `planny-serve-*.log` pattern in the temp dir as a migration
sweep. The detach and stop output lines keep printing the path.

*Pros:* siloed storage and siloed deletion with no scoping flags; the
name-by-port and port-0 warts disappear; another user's files can no
longer block a detach; temp-dir age cleaners cannot delete a live
board's log mid-run; "identify the log" becomes "look in .planny".
*Cons:* stores must be writable (they already are — serve.json);
most of today's clean-logs sweep logic retires the day after it
shipped; a machine-wide "how many old logs" view disappears because
there is no machine-wide pile to view.

## Alternative options

Keep logs in the temp dir but key them by store as well as port
(`planny-serve-<port>-<hash-of-store-root>.log`). `--clean-logs`
defaults to files matching this store's hash; `--global` sweeps them
all. Preserves a machine-wide pile and today's sweep code. Ruled out
for now: the hash is opaque to a human, the port-0 catch-all needs a
rename dance to fix, and temp-dir age cleaners can still delete a live
log.

## Needed from you
