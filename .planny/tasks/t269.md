Noticed while starting the first shared board, 2026-09-02. `planny serve --all
--detach` was run from planny-wanny and printed:

  log: /mnt/user-data/mike/claudebox/.planny/serve.log

The log went to claudebox because detachServer takes its working directory
and its log path from the first plan in the list, and the list is sorted by
path. For a single-plan board that is exactly right — the log belongs to the
plan being served. For a shared board it names a plan the operator did not
mention and may not be thinking about.

Done looks like: a shared board's log goes somewhere that means "the shared
board", not "whichever plan sorted first". Two candidates worth weighing when
this is picked up: the directory the command was run from, when it holds a
plan; or one path per machine, beside the other transient files of the plan
the operator invoked it from. Either way `serve --stop` and `--clean-logs`
must find it, and `--clean-logs` must not delete a live shared board's log.

Not urgent: the address, the stop and the clean-up all work today. It is the
printed path that misleads.

Files: src/server.ts (detachServer, serveLogPath, cleanLogs), src/cli.ts.
