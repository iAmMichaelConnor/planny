Built, 2026-09-02, together with t256 (the column counts) because both change
the same header and the same filter bar.

The board's filter bar gains a status chip per column, the same control the
tree already uses. A chip carries the status name and the number of cards that
status holds after the kind and type filters apply, so a hidden column still
says how much it is holding. Clicking a chip shows or hides that column, and
the choice is remembered in this browser.

The default is exactly what the board did before: the three working columns
always, and Parked or Cancelled only once the store holds one. That default
stands until the operator clicks a chip; from then on their choice wins. So
nobody's board changes shape until they ask it to.

t256). How to test: npm test (530 pass). Runs at: the board, filter bar.
