Why: the board has had no accessibility pass. Status reaches the eye only as a
coloured dot, so a reader who cannot separate the colours cannot tell a
blocked card from a done one. The drawer opens without moving focus into it
and without trapping focus, so a keyboard reader stays stranded behind it. The
icon-only buttons in the header and the drawer (the theme button, the dock
buttons, the close button) carry a title but no accessible name. The tab strip
is a row of plain buttons with no selected state a screen reader can read.

Done looks like:
- Every status dot carries text or an aria-label naming the status, so colour
  is never the only carrier.
- The tab strip uses the tab pattern: role, aria-selected, and arrow-key
  movement between tabs.
- Opening the drawer moves focus into it and returns focus to the card that
  opened it when it closes.
- Every icon-only button has an aria-label.
- The toast area announces itself as a live region, so a warning is read out
  rather than only shown.
- The focus ring is visible on every control in both themes.

Notes: this is one pass over web/index.html, web/app.js and web/style.css, with
assertions in test/ui.test.ts. It needs no server change.


Built, 2026-09-02.

- Colour never carries meaning alone. Every status dot names its status
  through one helper, statusDot(status), and the same helper hides the dot
  from a screen reader where the word already sits beside it — a column
  header, a filter chip, the drawer title — so nothing is said twice.
- The tab strip is a real tab strip: role="tablist" on the nav, role="tab"
  and aria-selected on each button, aria-controls pointing at its panel, and
  each view a tabpanel. Left and right walk the strip and switch the view,
  and only the chosen tab is a tab stop, so Tab reaches the strip once
  instead of four times.
- Opening the drawer moves the focus into it, at the close button; closing
  hands the focus back to whatever opened it, found again by task id because
  the views rebuild constantly. A background refresh never moves the focus,
  or it would steal it mid-edit.
- Every icon-only control has a name: the theme button, the three dock
  buttons, the drawer close, the copy button, the dismiss button, and the
  tree's twist. The twist also says whether it is open (aria-expanded), and
  answers Enter and Space, as a thing calling itself a button must. The
  purely decorative arrow on a decision tile is hidden instead.
- The toast area is a live region (role="status", aria-live="polite"), so a
  warning is read out and not only shown.
- One :focus-visible rule draws the ring on every control, in both themes.

Note: t255 did part of this ahead of time — the roving tab stop on the cards
and rows means the keyboard walk moves real focus, which is what makes the
ring and the screen reader follow along.
