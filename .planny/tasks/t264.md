Audited, 2026-09-02. Method: read every command and every option out of the
built binary, run each one against a scratch store, and compare the result
with the README command table and the skill.

**What was stale.** One thing, and it was the biggest: the `decide` loop's
choices. That is fixed under t263 — it had no park and no cancel, and its
"skip" wrote nothing, which is the behaviour the operator had already replaced
on the board.

**What was dead or broken.** Nothing. Every option on every command runs and
does what it says, including the rarely used ones: `add --child`,
`update --add-child`, `--remove-child`, `--add-blocks`, `--remove-blocks`,
`--priority`, `--model`, `--clear-model`, `list --count`, `list --compact`,
`export --kind`, `progress --json`, `catchup --as --peek`, `init --nested`.

**What was missing from the docs.** The README command table had no row for
`decide` at all (added under t263), and four options it never mentioned:
`init --nested`, `add --json`, `list --count` and `list --compact`. The `bump`
row also predates t246, so it now says that a move stopping short names the
task that held it. The skill needed nothing: its action map and reference
already match the binary, and `park` and `--include-parked` joined them when
those shipped.

**What stops this drifting again.** Two tests, so the next stale option is
caught by the suite instead of by a reader:

- Every command the binary offers must open a row in the README command
  table. A new command with no row fails the suite.
- Every command must print its own help without falling over. That catches a
  command whose help text or option parser breaks, which is otherwise only
  found by a human running it.
