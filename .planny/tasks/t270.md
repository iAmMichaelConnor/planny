Raised by the operator, 2026-09-02, on seeing the shared board go live: are
there good tests that creating and modifying tasks through a project-scoped
route write into the intended project's .planny/ directory and no other?

Checked, and the cover was thin. One mutating route was tested across
projects — the status route — and it asserted through the Store object, not
against the files on disk. Every other write was untested across projects,
including the one that carries the most risk: creating a task. Ids are
allocated per store, so a create routed to the wrong project would both write
the wrong file and take an id from the wrong sequence.

Done looks like: every mutating route (create, update, status, cancel, bump,
resolve) exercised against the second project of a shared board, each
asserting the file it wrote exists under that project's own
.planny/tasks/ directory with the expected content, and that the other
project's task directory is byte-for-byte unchanged. Plus a test that ids
follow the target project's own sequence, not the first project's.

Files: test/server.test.ts.

Handed to the Fable 5.1 agent with the rest of the shared board (t271), 2026-09-02. The tests are written and green in test/server.test.ts but deliberately not committed, because the operator asked for no more shared-board commits until they are comfortable with the feature.
