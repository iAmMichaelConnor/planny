Decided in t266: the park note becomes an ordinary field on the parked task in the drawer, so it can be written after the fact, corrected, or left empty.

Today the drawer shows the note read-only (the `.parked-note` block), and the only way to write one is to park the task again. Replace that block with a form field:

- A one-line input labelled `parked until`, shown only while the task is parked, holding the current note.
- Help text that says plainly what it is: "A note for whoever picks this up. Nothing acts on it."
- The field saves with the rest of the form: "Save changes" sends it in the PATCH body, and typing in it marks the form dirty like every other field. Emptying it clears the note.
- The field carries no note when the task is not parked, so the PATCH body omits `parkedUntil` and cannot trip the ops rule.

Blocked by the ops work: the PATCH endpoint must accept the field first.

Done looks like: a parked task's drawer shows an editable "parked until" box with the help text; typing and saving rewrites the note; clearing it and saving removes it; UI tests cover both, and the box does not appear on a task that is not parked.
