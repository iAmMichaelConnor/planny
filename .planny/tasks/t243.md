Why: two stores served on one machine (planny-wanny on 5891, claudebox on 5892) need the operator or the agent to remember which port belongs to which store; 'planny serve --detach' with the default port fails or collides when the other store already holds it, and the skill text tells agents to report 'the URL it prints' without saying how to choose. Done looks like: serve --detach picks the first free port from a small range when none is given, records it in the store's serve state so 'planny url' and later serves reuse it, and the skill text says so.


Built, 2026-09-02. `--port` lost its default. With no `--port`, planny picks:
the port this store used last, then the first free port from 5891 upward,
skipping anything already listening. Twenty ports are tried; when all are
busy the error says to pass `--port`. An explicit `--port` still binds exactly
that port and fails exactly as before, so nothing an operator scripted
changes. `--port 0` still means "let the operating system choose".

The memory lives in `.planny/serve-port`, one line, written on every bind and
never deleted — not in `.planny/serve.json`, whose job is "a server is up
right now" and which every clean stop removes. So a store keeps one address
across stops, restarts and crashes, and a bookmark keeps working.
`.planny/.gitignore` and the CLAUDE.md list of store files that ops does not
own both name the new file.

The direct (non-detached) `serve` walks the picked ports in order, so a racing
launcher that takes the chosen port between the probe and the bind costs one
retry instead of an error.
