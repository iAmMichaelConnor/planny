`git push origin` failed with "Permission denied (publickey)" during the 0.3.0 and 0.3.1 releases, so both pushes went over HTTPS with the gh token instead.

The cause is not the key. This machine reaches GitHub through the operator's forwarded ssh agent: `~/.ssh/rc` symlinks the forwarded socket to the stable path `~/.ssh/ssh_auth_sock` at each login, and `SSH_AUTH_SOCK` names that path. The symlink pointed at `/tmp/ssh-LT2lQGXkjU/agent.2685751`, whose ssh session had ended, so ssh offered no key at all.

Done looks like: `ssh -T git@github.com` greets iAmMichaelConnor, and `git fetch origin` and `git push origin` work with no extra flags.

Diagnosis confirmed 2026-09-02. The key on the GitHub account is good: three live forwarded agents all hold 'mike macbook 2026' (ED25519 SHA256:1yVN8ZrmYSBVC3lb4Ec+5U4OSkEBhnGdEXW8Tn9npt8) and each greets 'Hi iAmMichaelConnor!' over ssh. github.com:22 is reachable. Supplying a live socket inline proves the rest works: SSH_AUTH_SOCK=/tmp/ssh-j05cBqB1TW/agent.662150 git fetch origin succeeded, and git push --dry-run origin main reported everything up to date. The only broken thing is the symlink. The remaining step is one command, and it writes inside ~/.ssh, which this session is not permitted to do: ln -sf /tmp/ssh-j05cBqB1TW/agent.662150 ~/.ssh/ssh_auth_sock

Fixed 2026-09-02. The operator repointed the symlink at /tmp/ssh-j05cBqB1TW/agent.662150. Verified: ssh -T git@github.com greets iAmMichaelConnor, git fetch origin, git ls-remote origin and git push origin all work with no extra flags. The key was never the problem; only the symlink was stale.
