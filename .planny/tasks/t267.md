Found while starting the first `serve --all` board, 2026-09-02. Scanning the
home directory turned up six plans, and three of them were scratch copies
under ~/.claude/jobs/bd99f8a4/tmp/ — fixtures a job left behind, not projects
anyone plans in. A picker listing those is a picker nobody trusts.

Cause: the walk skips a named list of noisy directories (node_modules, dist
and the like) but happily descends into every hidden directory, and a home
directory is full of them: .claude, .cache, .local, .npm, .vscode.

Done looks like: the walk passes over any directory whose name starts with a
dot. A plan lives in a project you work in, not inside a tool's private
directory, and `--root ~/.config` still reaches one deliberately if it is
ever really there. The scan also gets faster, because the dot directories are
where the file count is.

Files: src/discover.ts, test/discover.test.ts.


Fixed, 2026-09-02. The walk now passes over any directory whose name starts
with a dot. Before: six plans found under the home directory, three of them
scratch copies a job had left under ~/.claude/jobs/. After: three, all real
projects, and the scan is faster (1.6s against 2.5s) because the dot
directories are where the file count is.

The named skip list keeps only visible noise now — node_modules, dist, build,
out, target, vendor, venv, __pycache__, Library, Applications — because the
dot rule already covers .git, .cache, .next and the rest.

A hidden directory named as a --root is still searched. That is a deliberate
ask, and the rule should not overrule it.
