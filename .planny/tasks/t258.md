## Background

Every state-changing button on the board raises a browser `confirm()` dialog
first. The board calls it `guard()`, and its text always ends with the same
sentence: "Tip: an AI agent working this plan can make these changes for you
— consider asking it instead." The dialog fires on start, on done, on cancel,
on every priority move (top, bottom and a typed position), and in the
decisions tab.

This was deliberate. Task t25 ("Confirm dialogs on all status and priority
buttons") and t16 ("Confirm before drawer top/bottom bumps") both shipped, so
the pattern is the answer to an earlier question, not an oversight.

The cost shows up when the operator does several moves in a row. Reordering
five tasks means five modal dialogs and five readings of the same tip. A
browser modal also stops the page, so the operator cannot see the board while
answering the question about it.

## Why this comes to you (the operator)

You asked for these dialogs. Removing or softening them reverses a decision
you already made, and the friction is a matter of your own taste in your own
tool. It also touches the message the tool sends about who should be driving
the plan: the tip exists to push work towards the agent.

## Proposal

Keep a dialog only where the action is hard to undo, and replace the rest
with an undo. Cancel and reject keep their dialog. Start, done, todo, park
and every priority move act at once and raise a toast that says what happened
and offers "undo" for about ten seconds; undo posts the inverse through the
same API. Show the agent tip on the first action of a session only.

*Pros:* the common moves become one click; the operator sees the board change
instead of a modal; a mistake is still recoverable, and recoverable faster
than a dialog prevents it. *Cons:* it is more code than a dialog — the board
must remember the previous status or priority to post the inverse; an undo
that arrives after an agent has already acted on the change could surprise
both of them.

## Alternative options

- Keep every dialog, and drop only the repeated tip after the first one.
  Cheap, and it removes most of the irritation without new code. Weaker: the
  modal still stops the page on every move.
- Keep every dialog, and add a "don't ask again this session" checkbox, the
  way the add-task notice already works. Cheap and familiar. Weaker: an
  operator who ticks it loses the guard on cancel too.
- Change nothing.

## Needed from you

"undo", "drop the repeated tip", "add a don't-ask-again box", or "leave it".

## When

No deadline. It blocks nothing, but it touches every board action, so it is
worth answering before more buttons land (t248 adds drag-and-drop priority
moves, which would raise a dialog on every drop).
