The skill's rules say "Mutate through the CLI, never by editing task files by hand", which reads as a rule about editing existing files. Two adjacent mistakes are not named by that wording:

1. Creating a NEW task by writing an md file into .planny/tasks/ by hand instead of running planny add. Adding is a mutation too: a hand-written file skips id assignment, relationship bookkeeping, and history stamping.
2. Running the CLI from the wrong directory. The CLI acts on whichever store the current working directory holds, so a command meant for one project can silently target another project's store. Observed 2026-09-01: a cancel meant for the claudebox store ran while cd'd into planny-wanny; it failed only because the id happened not to exist there.

Make the skill convey both explicitly — for example, extend the mutate-through-the-CLI bullet to say: adding a task is a mutation (never create or edit files under .planny/ by hand), and run every planny command from within the project directory whose store you mean to change (cd there first; when in doubt confirm with pwd before mutating).

Done looks like: the shipped skill text names both hazards. Operator's words (2026-09-01): "You should not add md files to a .planny dir manually, you should use the planny cli tool (from within the relevant project dir) to add or update tasks."
