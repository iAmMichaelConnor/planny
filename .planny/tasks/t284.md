The operator asked for this on 2026-09-02, after asking what -N does.

`--forward` prints an ssh command whose only job is to hold the tunnel open.
Without -N that command also opens a login shell, which nobody types in: the
operator already has their own sessions on the machine, and this terminal
exists to forward ports. The stray shell is clutter, and closing it closes the
tunnel, which reads as the tunnel being fragile rather than as the shell being
beside the point.

Done looks like: the printed command carries -N, before the -L flags where
ssh's own examples put it. The note says what the terminal will do — sit there
holding the tunnel until Ctrl-C — because a command that prints nothing and
returns nothing looks hung to someone who has not met -N.

Not -f as well: backgrounding hides the tunnel, and then stopping it means
hunting a pid. A terminal the operator can see and Ctrl-C is easier to reason
about, and anyone who wants it in the background can add -f themselves.

Built, 2026-09-02. The printed command now starts `ssh -N `, before the port
flag and the forwards, where ssh's own examples put it:

  ssh -N -L 5890:127.0.0.1:5890 -L 5891:127.0.0.1:5891 mike@173.26.1.11

-N runs no remote command, so that terminal does one thing: hold the tunnel
open until it is interrupted. The help text and the README now say so, because
a command that prints nothing and returns nothing looks hung to anyone who has
not met -N.

-f is deliberately not added. Backgrounding hides the tunnel, and stopping it
then means hunting a pid; a terminal can just be interrupted. Anyone who wants
it in the background can add -f themselves.
