Today history records status changes only, so a priority bump leaves no trace and no actor. Generalize entries to typed events, each still one small line with {at, by}:

- priority: explicit moves only (bump or --priority), recording the requested target and the landing position. Mechanical renumbering — renormalize and dependency-order repairs — is noise and must never log.
- parent: set, cleared, or changed (from → to).
- blocked-by: each id added or removed. Covers cancel rewiring, which shows up as removals plus additions on the dependants.
- rename: old name → new name.
- status: as today.

Excluded on purpose: body edits (git and the file itself are the record; entries stay one line), kind/model/type tweaks (rare, low value — revisit if it hurts). Back-compat: existing {at, status, by} entries stay valid and parse as status events; the parser accepts both shapes. planny show prints the log; catchup (t35) can summarize typed events per task.
