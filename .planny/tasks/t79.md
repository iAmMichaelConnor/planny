Root cause from the t72 incident: an agent batch-ran add and start in one shell command, hardcoding predicted sequential ids; the operator's concurrent UI add consumed the predicted id and the agent blind-claimed the wrong task. Two fixes: (1) planny add gains --start, which marks the new task in-progress and claims it for the session in the same command — no second command, no id to predict. (2) The skill's Creating-tasks section states: take ids from command output, never predict them; another writer may take the next id at any moment; use add --start when you are about to work the task yourself.
