## What the shared board is

`planny serve --all` finds every .planny plan on the machine and holds them
in one server. The project name in the top-left of the board becomes a
picker. Plans stay completely separate: no view mixes two. It is live now on
http://127.0.0.1:5891 holding claudebox, codex-delegation and planny-wanny.

## Done looks like

A recommendation the operator can act on — keep it, cut it back, or take it
off main — with the work to match, and any question only they can answer

Verdict, 2026-09-02 (fable-boards). The shared board was too much for what
it gave — not in line count (its replacement costs about the same) but in
where the lines sat: inside the board's server and UI, changing how every
request was routed and what every plan's address record meant, and making
one process and one UI build serve every plan. The operator's own steer
arrived while this was being judged ("a thin site that points to the other
planny sites", then "a single command that launches all plannys ... and
gives the user one link", and a forward helper), and it is the better
design: each plan keeps its own board and its own build; one command
starts them all and serves one page that links them.
