The skill (skills/planny/SKILL.md, section "Working tasks", step 3) says to mark a task done the moment it is finished. Add one sentence: done follows a verified landing. When a script marks a task done, that command runs only after the merge, the clean-tree check and the tests have each succeeded (chain with && or check each result). A done recorded before the evidence exists is a false record that costs a reopen.

Why: on 2026-09-02 a landing script in the claudebox project marked three tasks done while the merge was still open or a test had failed (claudebox coverage/HISTORY.md line 2772). The skill is the one file every planny user reads, so the rule belongs there as well as in that project's working rules.

One wording question is open in the claudebox store as decision t424: when a subagent builds a branch and an orchestrator merges it, does the subagent's done mean "green and handed off" (with the landing as the orchestrator's own task), or does only the orchestrator close the task? The skill already says work with several owners becomes child tasks with one owner each; the added sentence should match whichever shape t424 settles on. Write the sentence after t424 is decided.
