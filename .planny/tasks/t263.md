Should the planny decide cli options be revised to more closely align with the ui options and wording of options? Are those cli options stale? Are the codepaths that the cli commands connect with stale?


Audited and fixed, 2026-09-02. The answers to the three questions in the task:

**Were the options stale?** Yes, in two ways. The loop offered
"[a]ccept proposal / [r]espond / [x] reject / [s]kip / [q]uit". The board
offers Submit, Accept proposal, Reject, Park for now and Cancel decision. So
the loop had no park and no cancel, and its "skip" was the very thing the
operator replaced in the board: a skip that wrote nothing and was forgotten
the moment the loop ended. Its "respond" was also the old word for what the
board now calls Submit (renamed in t194).

The loop now offers "[a]ccept proposal / [s]ubmit answer / [x] reject /
[p]ark / [c]ancel / [n]ext / [q]uit" — the board's five actions in the board's
words, plus next and quit for moving through the queue. Park asks for the
wake note, exactly as the board does. Next is the old skip under an honest
name: it records nothing and the decision stays where it was.

**Were the codepaths stale?** No. decide calls nextDecisions, renderShow,
resolveDecision and report, and all four are current — nextDecisions already
passes parked questions over, and resolvedLine already names the outcome task,
which is what the board's green confirmation says too.

**Two defects found while checking, both fixed.**

One: since t245 a second resolve on an answered decision is refused. The loop
reads its queue once at the start, so a decision answered in another shell
mid-loop made the whole loop throw and abandon the rest of the queue. Each
action is now caught on its own: the failure is reported against its id and
the loop moves to the next question.

Two: the loop hung forever on input that ends — `planny decide < answers.txt`,
or a closed terminal. Node's readline never settles its question at end of
input. The end of input now reads as "quit", so the loop finishes and the
command exits.

Also: the README command table had no row for decide at all. It has one now.
