When on the decisions tab, the button to move a decision to the bottom isn't working: it doesn't seem to change the priority of the decision task, and it doesn't seem to visibly put the decision box at the bottom of the list of  decisions. Seems like a bug. This might affect the top/bottom and granular priority number adjustment. 

Cause found, 2026-09-02. The button worked; the move was clamped and nobody said so. The store's own history holds the evidence: t68 logs `event: priority, target: bottom, position: 2`. At that moment t152 was active and waited on t68, so the invariant "a task never ranks below a task that waits on it" held t68 at position 2. The CLI prints the landing position; the board printed nothing, so the move looked dead.

Fix: ops.bumpTask now compares the landing position with the requested one. When a dependency holds the task back, it returns a warning that names the position and the task that binds it. The warning travels the one path both surfaces already read: the CLI prints it to stderr, and the board shows it as a warn toast. Down-clamp names the highest-ranked active task that waits on the moved task; up-clamp names the lowest-ranked active task it waits on. A move stopped only by the length of the list stays silent.

Also fixed: the server's bump route dropped the actor, so every priority move made from the board was unattributed in the history. It now passes actorOf(body), the same as every other route.
