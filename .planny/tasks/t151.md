When in the tree view, it currently shows nested parent-child relationships. That's great. And it shows which tasks are waiting on other tasks. Can we make that waiting clearer, by whenever the user hovers over a task which is waiting on other tasks, red curved lines come out of the right of the task (where its text finishes) curving out rightward and back in to the right of the task(s) that it is waiting on. And then another level of slightly dimmer red lines coming out of those to the task(s) that they are waiting on, and so on.

I also wonder if there would be a benefit in having a version of the tree view toggleable which orders by dependencies instead of parent-child relationships? I know we have the dependencies section with a graph, but perhaps a tree-view is also useful. The most blocking things would be at the top level, with things that are blocked by it nested, at however many layers are needed, know what i mean? You should re-use the code for tree visualisation that we already have and re-use as codepaths wherever possible. Keep code clean, no unnecessary duplication, well-tested.

Built (2026-09-01): hovering a tree row draws red curves out of the right of its text to each active blocker, then dimmer curves level by level down the chain. A nest-by select switches the tree between parent → child and blocker → blocked; the two orders share one renderer. Files: web/app.js, web/style.css. Tests: test/ui.test.ts, suites 'tree hover dependency lines' and 'tree dependency order'. Shipped in 0.1.8.
