Two clicks on the board's Create button, faster than the request, add the task twice. The operator's own quick-adds t300 and t301 are one request written 240 milliseconds apart, word for word the same, both attributed to `operator`: the duplicate cost a cancel and a rewire.

The form posts to /api/tasks from `#save-btn` in web/app.js (wireDrawer, the isNew branch) and nothing stops a second click while the first is in flight. The Save path on an existing task has the same hole: a second PATCH races the first and the loser is refused for a stale `ifUnchangedSince`.

Hold the button against a second submit while a save is in flight, in one place that covers both the create and the update path.

Done when: a test in test/ui.test.ts clicks Create twice inside one request and sees exactly one POST to /api/tasks, and `npm test` is green.
