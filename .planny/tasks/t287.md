Decided in t266: the park note stops being asked for at park time and becomes an ordinary field the reader can write, correct or empty later. This task opens the funnel that makes the field editable.

Today only `setStatus` carries `parkedUntil`, so the note can only be written by parking the task again. Add it to `updateTask` as well:

- `UpdateInput` gains `parkedUntil?: string | null`. Text sets the note; `null` or a blank string clears it.
- The task must be parked. Any `parkedUntil` on a task with another status is refused with the message `setStatus` already uses: "a wake note belongs to the parked status only". This keeps the doctor's invariant (a `parked_until` on a task that is not parked is a fault).
- No history entry: a note edit is a field edit, like the body.
- `assertUpdateInput` validates the shape, because the server passes JSON bodies straight through.
- The server's PATCH `/api/tasks/:id` passes the field on.
- The CLI gains `planny update <id> --until "<text>"` and `--clear-until`, so the note is editable from the terminal too, not only from the board.

Done looks like: ops, server and CLI tests cover setting, changing and clearing the note, and the refusal on a task that is not parked. `planny update t9 --until "the API ships"` on a parked t9 rewrites the note and leaves the status alone.
