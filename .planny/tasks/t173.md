Companion to the skill-side placement rule: the CLI can catch what wording cannot. Observed 2026-09-01 in the claudebox store: an agent created "Fable-review the Opus-only window of 2026-08-28/29" (t202) while "Fable review pass over the sessions-23-25 core slices" (t30) sat open in the tree — same work, different words; the duplicate was found only by a later manual tree read.

Proposal: planny add compares the new task's name (and maybe first description line) against open tasks — simple token overlap is enough, no embeddings — and when a likely match exists, prints a non-blocking warning on the confirmation line: "added t202 — ... (similar open task: t30 'Fable review pass over the sessions-23-25 core slices' — planny cancel --replaced-by if this supersedes it)". Non-blocking matters: multi-writer agents must not hit interactive prompts. An opt-out flag (--no-similar-check) or env for bulk migrations.

Value: in a multi-writer store (several agents adding concurrently) name-similarity at write time is the only cheap point where duplicates can be caught before they fork history.
