Enable a user to filter (on the kanban and tree view):
- Tasks created/status-changed/started/done/edited between two dates.

Have a think about whether there are any other USEFUL changes that should be covered by this filter


Built, 2026-09-02. Both filter bars gain the same three controls: a "which
event" select, a from date and a to date, three presets (today, 7 days, 30
days) and a clear button.

The events it can match, all read from what the store already keeps — the
created stamp, the updated stamp, and the typed history:

- any change (the default): made, edited, or any recorded action
- created
- started
- finished
- status changed (any of them, cancelling and parking included)
- priority moved
- renamed
- re-parented
- dependencies changed

Those cover the operator's list and the other useful actions history records.
Two things a date filter cannot honestly offer, and why: there is no "edited
between two dates" beyond the single updated stamp, because a task keeps only
its latest edit time — the history covers everything else; and there is no
"who did it" filter here, because that is a different question and the kind
chips already answer part of it.

Decisions taken, worth knowing:
- One window serves both views, not one each. "What happened this week" is a
  question about the plan, not about the view you are standing in, and the
  bar shows the window in both places.
- The window is whole days in the reader's own time zone, both ends included,
  so "22 Aug to 22 Aug" means all of that day.
- An empty end is no bound on that side.
- The window is not remembered between visits. A stale window on the next
  open would hide the plan and look like data loss.
- Column counts follow the window, so a filtered board never claims a size it
  is not showing.
