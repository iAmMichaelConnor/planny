Caught by the operator, 2026-09-02, straight after the merge. The skill, the
README and `serve --help` all print this one-liner:

  ssh $(planny serve --all --forward) <host>

It does not work. The `$(...)` runs in the shell that types it, which is the
machine the operator sits at — their laptop. planny is not installed there
and the plans are not there either. The flags have to be produced on the
machine that serves the boards, and used on the machine that opens the
tunnel. Those are two different computers, and the whole point of the
forward is that they are.

Done looks like:
- `--forward` prints a complete line the operator can paste, not a fragment
  that invites the broken substitution: `ssh -L … -L … <host>`, with the
  placeholder left for them to fill in. A fragment reads like something to
  compose; a command reads like something to run.
- The skill, the README and the help text say plainly which half runs where:
  produce the line on the machine that serves, paste it on the machine you
  sit at.
- The help text keeps a correct one-liner for anyone who wants one, and it
  has to name the host twice, because that is what it really takes:
  `ssh $(ssh <host> planny serve --all --forward | sed 's/ <host>//') <host>`
  is honest but ugly; judge whether it earns its place or whether the
  copy-and-paste instruction alone is better.

Fixed, 2026-09-02. The operator was right: the one-liner was wrong in the
skill, the README and `serve --help`.

`--forward` now prints a whole command rather than a fragment:

  ssh -L 5890:127.0.0.1:5890 -L 5891:127.0.0.1:5891 <host>

That single change removes the trap. A fragment reads like something to
compose, and the obvious composition — `ssh $(planny serve --forward)
<host>` — substitutes in the shell that types it, which is the operator's own
machine, where planny is not installed and no plan exists. A whole command
reads like something to paste, which is exactly what it is.

The host stays a placeholder. This machine cannot know what the operator
calls it; its own hostname is often not the name they ssh to, and guessing
wrong is worse than an obvious blank.

All three places now say which half runs where: produce the line on the
machine that serves the boards, paste it on the machine you sit at, and do
not wrap it in a substitution. The skill's version tells the agent to hand
the printed line to the operator rather than to run anything itself.

No one-liner is offered. An honest one has to name the host twice and strip
the placeholder — `ssh $(ssh <host> planny serve --all --forward | sed …)
<host>` — which is longer to read than the two steps it replaces, and opens
a second connection to save a copy and paste.
