Decided in t266: parking is one click again, and the note moves into the drawer (t289).

Today every park on the board opens a `prompt()` asking "Park <id>. What should bring it back? (optional)". The question promises more than the field delivers — nothing acts on the note — and it interrupts a gesture that should be quick. The board has offered undo on every action since t258, so a mis-click is already cheap.

Remove the prompt from all three park paths in web/app.js:

- `parkTask(id)` (the decisions tab's "Park for now" button, and the drawer's `parked` status button) parks at once: `setTaskStatus(task, 'parked')`.
- `moveTaskToColumn` (a card dropped on the Parked column) drops its `parkedUntil` question and parks with the drop.

The undo path stays exactly as it is: `inverseStatus` already carries an existing note back when it restores a parked task, so undoing a park that followed a park keeps the old note.

Done looks like: clicking Park parks the task at once and raises the usual undo toast; no `prompt` call is left in a park path; UI tests cover the button and the drop, and assert the request body carries only the status.

Files: web/app.js, test/ui.test.ts. Run `npm test`.
